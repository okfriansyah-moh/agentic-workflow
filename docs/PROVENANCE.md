# Source and adaptation record

The 47 reused skills are snapshots of the user's installed local skill directories. Supporting references, scripts, evaluation fixtures, datasets, metadata and existing licenses are retained; dependency caches and filesystem metadata are omitted. Original source tree digests and each installed tree digest are in manifest.json. A digest identifies a local snapshot without pretending it is an upstream release. Materials without a recorded redistribution grant remain private personal source; publication needs a separate license review.

Portable changes replace personal absolute paths with bundle-relative references and user-level storage configuration. The shared wording policy/checker is under resources/wording. Document helper defaults resolve it from their installed file. Task Observer defaults to the user's .codex/skill-workspace and accepts AGENT_WORKFLOW_OBSERVATIONS; it creates no schedules, services or hooks. Existing original global skills are preserved by installation conflict rules.

The reused TDD skill accepts already-approved test boundaries and permits the independent stored-state observation required by ATDD. Code review keeps Standards/Spec evidence but feeds one independent findings ledger rather than requiring nested orchestration or an unavailable issue-tracker setup skill. UI recommendation guidance remains conditional on the adopted design and selected framework. The UI/UX search entrypoint was rewritten to remove a fixed React Native stack, compulsory design generation and automatic persistence; complete supporting search data/scripts remain available. The review entrypoint uses supplied local sources and one existing reviewer without missing tracker-document dependencies. Upstream evidence and negative checker fixtures are retained as evidence, not new output templates.

Seven workflow adaptations derive from the supplied Billing/Officeless skills and latest Forge attachment. They retain task traceability, bounded correction loops, worker reuse, focused self-review, real telemetry and readable evidence. They remove company paths, Ruby/Go-specific rules, fixed models, duplicate approval interviews, tracker/wiki writes, external notifications and predicted quality verdicts. Latest backend and review-verify attachments inform the role catalog; backend now follows selected Kotlin/Node boundaries, and review uses actual checks with the selected 80% changed-line policy.

Anti-slop derives from [Miqdad Badjuber's repository](https://github.com/miqdadbadjuber/anti-slop/tree/b1cdf87d49b1653293d58424516fd80394008345), revision `b1cdf87d49b1653293d58424516fd80394008345`, upstream version 3.2.20, MIT license. Each of its six adapted skills contains the unchanged license and source digest. The adaptations retain purposeful design, factual copy, usability, responsive behavior and comment hygiene. They honor adopted artifacts, share one review process, remove installation/mode interviews, and replace blanket aesthetic/comment-length rules with evidence-based review. The contrast arithmetic helper is retained under antislop-human with corrected large-text units and the current sRGB breakpoint. Its retained eight-pair reference table passes the helper self-test. It is a color-pair tool, not a full accessibility audit. The unit definition follows [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Forge also applies bounded native delegation concepts from the user's existing running-prompt, parallel-dev and subagent-driven-development guidance; these are not additional installed entrypoints. Worktree ownership and semantic integration are adapted conceptually from [Skeleton Parallel](https://github.com/okfriansyah-moh/skeleton-parallel), without copying its daemon/router architecture or application constraints. All role models inherit host settings.

Authoring version: 1.0.0. The reusable source stays local. The installer records actual managed files and backs up changed installation state separately; this provenance document is not evidence that a host has loaded the resources.

Role and workflow routing opens the selected bundle skill path explicitly. This prevents retained same-named global versions from replacing a repository adaptation during execution. Worker roles return to the parent and independent reviewers keep product source and task status unchanged.
