# antislop-ui

Read antislop and the adopted design specification/tokens. Start with the user's main task, actual content and state hierarchy. The approved palette, typography and component system govern; this review does not replace them with a new aesthetic.

Inspect hierarchy, density, spacing rhythm and alignment in real rendered states. Give primary actions and essential information clear emphasis. Use cards when grouping is meaningful, avoid boxing every paragraph, and let differing content needs shape layout. Keep component radius, shadows, icon family and motion consistent with tokens.

Check whether each gradient, glow, background texture, badge, arrow or illustration helps meaning or interaction. Remove empty decoration; keep justified visual choices without writing repetitive rationales for every element. Use real images/assets when the task calls for them and label fixture content honestly.

Verify navigation targets, button outcomes, forms and the required loading/error/empty/success states. Avoid inert controls and claims of functionality based only on a static mockup. Confirm each shipped theme has readable contrast and coherent surfaces.

Inspect narrow/intermediate/wide layouts and content extremes. Record actionable defects with screenshot/state and file references. Feed them into the existing review ledger; design preferences remain suggestions unless they contradict an adopted requirement. Recheck corrected surfaces and report actual observations.

Apply the [shared wording policy](../../resources/wording/output-wording.md) to authored output. Read supporting skills only for the current task.
