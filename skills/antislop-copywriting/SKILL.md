# antislop-copywriting

Read the product behavior, adopted design and intended audience. Use actual task/domain vocabulary and the adopted brand voice. Personal voice is supplied by humanizer only when requested; this skill does not invent testimonials, usage counts, savings or capabilities.

Give each heading, label and sentence a concrete job. Name the action or result rather than promising vague transformation. Remove generic openings, repeated value propositions, adjective stacks, unsupported superlatives and sentences that restate the heading. Prefer a precise short statement to a slogan when the user needs information.

Check button labels against their actual effect, error messages against the failure and recovery path, and empty states against the next useful step. Keep destructive-action and permission text accurate. Do not expose internal architecture or implementation terminology unless it helps the product user decide.

Distinguish verified facts, expectations and illustrative placeholders. If required factual content is missing, retain an honest labeled placeholder or report the gap; do not fabricate logos, reviews, customer quotes, statistics or certifications. Reuse approved content where it already fits.

Review text in context at relevant viewport sizes and states. Preserve terminology across the journey, include accessible labels, and keep required legal/security meaning intact. Run the shared wording checker over complete authored copy and completion text. Return focused corrections and factual gaps through the normal review process.

Apply the [shared wording policy](../../resources/wording/output-wording.md) to authored output. Read supporting skills only for the current task.
