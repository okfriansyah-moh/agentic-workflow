# Verification and completion

Run `scripts/check_artifacts.py <package> --source <primary-document>` from the project root (`--prd` remains compatible). Use `--layout standard` for new output; `auto` detects `mockup/` and `legacy` preserves older contracts. It checks required files by layout/version/target, source freshness, dispositions, referenced acceptance IDs, mapping agreement, artifact format/target/state references, index reachability, token aliases/overrides, CSS when HTML is present, local links, duplicate HTML IDs, and nesting between declared independent states. Standard packages also reconcile every defined NFR and AC through explicit dispositions. It does not measure contrast, decode/prove raster design fidelity, exercise runtimes, or certify accessibility, permissions or backend behavior.

Reconcile every UI-affecting quality requirement and acceptance scenario with an actual state example or documented nonvisual rationale. For briefs/GDDs without FR/AC tables, review extraction completeness and source excerpts manually. A structural pass cannot prove the meaning or completeness of visual coverage.

## Match evidence to the target

- **Web/HTML previews:** serve locally when needed; inspect every linked state in each declared theme/viewport context, with long content/missing assets where meaningful. For mutually exclusive state previews, require exactly one intended active state with visible content and nonzero layout dimensions; inspect computed display/visibility and hidden ancestors, not only the element’s own `hidden` attribute or anchor existence. Confirm the visible heading/content matches the requested scenario. For simultaneously visible comparison examples, verify each intended region and its label instead. Open direct links, exercise every available state-selector option, and check browser back navigation. Exercise representative controls, forms, dialogs and recovery by keyboard. Check focus/order/return, labels/error associations, persistent feedback, contrast combinations and reduced motion. HTML simulations for mobile/games prove only the browser demonstration.
- **Native mobile:** inspect available captures and annotated states; exercise safe areas, orientation, text scaling, gestures/back, input obstruction, accessibility and recovery with the declared device/simulator/runtime when available. Static images cannot prove those runtime behaviors. Apply OS references only to selected targets.
- **Games:** inspect HUD/menu legibility over relevant play backgrounds, safe display regions, scaling and feedback states. Exercise declared touch/keyboard/controller navigation, selection/back, pause/resume and accessibility with an available declared-engine preview. Static storyboards cannot prove input behavior, frame timing, audio/haptics or engine integration.
- **Unspecified or multiple targets:** inspect shared foundations and each target's documented overrides. Keep unresolved platform/runtime choices explicit. Record checks per artifact and target, not a blanket “mobile verified” based on a narrow browser width.

Record checks, results and limits in the specification’s `## Validation and handoff` section. Capture actual screenshots/captures when useful; keep representative evidence under `mockup/assets/` and temporary matrices outside the handoff package. Review labels and semantics as well as pixels. Record methods/results for measured contrast; images showing a denied state do not demonstrate authorization enforcement. If a tool, renderer, adapter or asset is missing, complete available static work and mark the precise remaining checks pending. Do not fabricate measurements or runtime evidence, and do not install/build a framework or engine solely to satisfy a documentation review unless that work is authorized.

Use a bounded pass: batch relevant target/state inspection, fix observed defects, then confirm those corrections. Repeat only for unresolved defects or new changes.

Completion requires design specification and token JSON agreement; applicable exports/overrides consistent with the base; usable linked visual indexes/catalogs; truthful role/player-aware source coverage; real visual examples for consequential states; structural validation and honest target-appropriate evidence or explicit material limitations. Final handoff leads with a clickable `design-system.md` link, followed by other useful output paths, adopted direction, verification and unresolved choices. Production implementation remains a separate outcome.
